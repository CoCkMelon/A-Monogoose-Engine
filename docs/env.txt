ame-next ENGINE SPEC
File: env.txt - every environment variable the ENGINE reads

WHY THIS FILE
state-audit.txt #4: 14 variables were read in src/, 3 were documented. An
undocumented variable is state the app did not declare: it changes what the
program does, is invisible at every call site, and - worst of the five - one
of them (AME_FIXED_FRAME_DT) silently replaced the loop policy AND the
threading model. This file is the complete table, and tools/ci_drift_check.sh
fails the build if src/ reads a variable that is not listed here, so the
table cannot rot.

HOW TO READ IT
  Column EFFECT says what changes. "VALUE" = a number/size/string.
  "MODEL" = a change in how the program runs (threading, timing, capture
  path) - the ones worth suspecting when behaviour differs between two runs
  that "should be the same".
  Every variable below is read ONCE at startup, applied, and reported with
  one log line naming the variable and the value it replaced: the engine
  never changes behaviour because of an env var without saying so
  (app_loop()'s own line covers the loop descriptor; see loop.txt).
  Unset always means "use the declared/default behaviour". These are
  developer and QA knobs, not features: shipping an app that REQUIRES one is
  a bug in the app.

LOOP / TIME  (see loop.txt, time.h)
  AME_LOOP_VARIABLE   VALUE+MODEL  Force the VARIABLE mode: logic runs on the
                                  frame thread as app_step(dt). Overrides the
                                  mode app_loop() declared.
  AME_LOOP_HZ         VALUE        Force the FIXED step rate (steps/second).
                                  Does not change the mode.
  AME_LOOP_MAX_STEPS  VALUE        Force the per-wake gate: excess whole steps
                                  are DROPPED (counted), never caught up.
  AME_FIXED_FRAME_DT  VALUE+MODEL  Deterministic captures: run exactly dt of
                                  logic INLINE per rendered frame and DO NOT
                                  create the logic thread. Replaces the
                                  declared loop policy outright; frame N
                                  always shows sim time N*dt. Logged with the
                                  policy and the threading model it replaced.

WINDOW / PLATFORM  (app_sdl.c)
  AME_WINDOW_W        VALUE        Window width in px at creation.
  AME_WINDOW_H        VALUE        Window height in px at creation.
  AME_WINDOW_TITLE    VALUE        Window title override.

LOGGING
  AME_LOG_FILE        VALUE        Also write the engine log to this path
                                  (headless CI captures, bug reports).

CAPTURES  (app_sdl.c; examples with their own hook are noted in EX.)
  AME_SHOT_PPM        VALUE+MODEL  Write a P6 PPM to this path after
                                  AME_SHOT_FRAMES frames. Implies a capture
                                  build of the frame loop.
  AME_SHOT_FRAMES     VALUE        Which frame to write (default 5).
  AME_SHOT_NOFLIP     VALUE        Do not flip the readback vertically: for
                                  TOP-LEFT-origin captures.

FILESYSTEM  (fs.c)
  AME_PREF_PATH       VALUE        Root for preference/config files instead of
                                  the platform default (tests, portable
                                  installs).

APP-LEVEL VARIABLES (examples/, templates/) - NOT engine behaviour
  These are read by example apps, listed so a reader knows which "AME_*"
  name is not part of the engine contract:
    AME_AUTOPLAY, AME_FAKE_MOUSE, AME_NO_LOOP, AME_SEED, AME_SERVER,
    AME_SCREENSHOT, AME_SCREENSHOT_FRAMES, MEM_IDLE_EXIT, MEM_TIME_SCALE,
    AME_ED_TEXT, AME_ED_CARET, AME_ED_SOLID_CARET, AME_ED_SMOOTH,
    AME_ED_TRACE, AME_OPUS
  The rule for new example knobs: prefix with the EXAMPLE (MEM_, AME_ED_)
  or add to this list in the same change set.

PYTEST / CI SHORTHANDS (read by tools/*.sh, never by the engine)
  SDL_VIDEODRIVER=offscreen, SDL_AUDIO_DRIVER=dummy, LIBGL_ALWAYS_SOFTWARE=1
  are the headless recipe used by tools/smoke.sh; they are SDL/Mesa
  variables, not engine ones.

ENFORCED
  tools/ci_drift_check.sh greps src/ for getenv("AME_...") and fails if a
  name is missing from this file. Adding a variable therefore requires
  documenting it in the same change set.

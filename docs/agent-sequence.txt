ame-next ENGINE SPEC
File: agent-sequence.txt - the subagent pipeline, stage by stage

WHY THIS FILE EXISTS
Recorded 2026-11-19: the deadline that shaped earlier estimates is
gone, so this pipeline optimizes for CORRECTNESS PER STAGE instead of
speed. The shape follows from that: every BUILD stage is followed by a
VERIFY stage run by a different agent, and MEASURE stages run wherever
a decision needs a number before code does. A stage that is not
verified did not happen.

=====================================================================
HOW TO INVOKE A STAGE (paste, fill in the stage id)
=====================================================================
  You are stage <S#> of the ame-next subagent pipeline.
  Read, in this order: docs/agent-sequence.txt (the rules for every
  stage, then YOUR stage brief), AGENT_HANDOFF.txt, docs/agents.txt,
  docs/principles.txt, docs/components.txt, docs/plan-3d-puzzle.txt,
  and the GitHub issue your brief names - including its latest
  comments. The coordination hub is issue #3.
  Execute your stage brief exactly. End green: build, ctest, the
  sanitizer trees and goldens your brief requires, drift gate, commit,
  push, and the remote sha verified through the branches API.
  Then post your stage report as a comment in that issue, and set your
  stage's STATUS line in docs/agent-sequence.txt in the same commit.
  If your brief's premise turns out to be wrong, STOP and report the
  measurement in the issue instead of working around it.

=====================================================================
RULES FOR EVERY STAGE
=====================================================================
1. The remote branch ame-next-trunk is the source of truth. Sandboxes
   are rewound without warning (23 recorded): fetch, compare the tip,
   and reset --hard onto the remote tip BEFORE working. Local commits
   that were never pushed are gone after a rollback.
2. Dependencies vanish with the sandbox. Reinstall list is in the hub
   (#3) and AGENT_HANDOFF.txt; from the baker stage onward it includes
   libassimp-dev (measured: with it, tools/assimp2c builds -
   "assimp 5.4.3"). Blender 4.3.2 is also installable headless, so
   fixtures are GENERATED BY SCRIPT (blender -b --python ...), never
   hand-made, and are committed.
3. Every stage ends: build OK, ctest green (32 or more, NEVER fewer),
   commit, push, and the remote sha verified by API. Push output alone
   is not proof; a push made while HEAD was rewound has already
   published a stale tip once.
4. Gates: a change touching include/ame/*.h must touch docs/ in the
   same commit; a NEW public header needs its own docs/<stem>.txt;
   every getenv("AME_*") in src/ must appear in docs/env.txt. Run
   tools/ci_drift_check.sh locally before pushing.
5. Justify objectively - measurement and technical merit, never
   ownership or authority (recorded 2026-11-14).
6. A VERIFY stage adds no features. It rebuilds from the remote tip,
   re-runs the previous stage's claims with the same commands, and
   either confirms them with numbers or files the defect in the issue.
   Fixing a defect it finds is in scope; growing scope is not.
7. Update this file: every stage has a STATUS line, set by the agent
   that finishes it, in the same commit as the work.
8. Never run two stages that touch the same files concurrently. S10 is
   the only stage with tree-wide reach into render.c and every example;
   it gets the lane to itself.
9. No engine-side defaults (recorded 2026-11-18): configuration is
   struct values with every field named, and a call that cannot take
   effect fails loudly instead of silently doing nothing.
